Three workspaces, one formal-language toolkit

Each workspace targets a different representation—machines, grammars, parsers—with transfers between them in the desktop app.

Machine Studio Grammar Lab Parser Studio
Machine Studio

Draw, run, and convert automata

Interactive canvas for finite automata, pushdown machines, transducers, and Turing models—with step, play, and batch testing.

Concepts: recognition, nondeterminism, stacks, tapes, computation trees (NFA, NPDA, NLBA).

  • Conversions such as ε-removal, subset construction, DFA minimization, regex→NFA, FA→regex, CFG→PDA, PDA→CFG, Mealy↔Moore.
  • Analyze reachability, dead states, and emptiness on finite automata (DFA/NFA/ε-NFA); export traces and computation trees from the desktop app.

Try: Build a DFA for even zeros, minimize it, then extract an equivalent regular expression.

Browser demo → Machine guide →
Grammar Lab

Grammars with analysis that respects the Chomsky type

Edit regex or Types 0–3 grammars; tabs unlock only when the format supports them (CFG tools do not run on unrestricted grammars).

Concepts: FIRST/FOLLOW, nullable symbols, CNF/GNF, ambiguity (Type 2), bounded derivations for Types 0–1.

  • Properties, sampler, derivations, transformations, ambiguity, FIRST/FOLLOW, and problem diagnostics—gated per format.
  • Send grammar text to Parser Studio or build standard machine recognizers without retyping rules.

Try: Enter a small CFG, compute FIRST/FOLLOW, then convert to CNF for CYK in Parser Studio.

Desktop app required → Grammar guide →
Parser Studio

Parse tables, item-set graphs, and stepped parses

Build LL and LR families, CYK, Earley, or recursive-descent backtracking on the same grammar syntax as Grammar Lab.

Concepts: predictive parsing, canonical LR, conflicts, syntax trees, parse timelines.

  • LL(1), LR(0), SLR(1), LALR(1), CLR(1), CYK, Earley, and backtracking—with conflict reporting for table-driven methods.
  • Stack/buffer views, syntax trees, batch input runs; LR automaton graph (hidden above ~1500 states—tables and simulation still work).

Try: Import an expression grammar, inspect the LALR(1) table, and step through a parse with the timeline.

Worked example: regex → NFA (Thompson construction)

A static walkthrough of a conversion that exists in Machine Studio today. This is not a live simulation—follow the steps in the desktop app or read the machine guide.

Desktop app Regex → NFA is a Machine Studio construct. The browser demo does not replace the full conversion UI.

  1. 1. Input — regular expression

    Choose Regex → NFA (Thompson’s construction) and enter a pattern such as:

    (a+b)*abb

    Classic “strings ending in abb over {a,b}” language from automata courses.

  2. 2. Intermediate — ε-NFA fragments

    AutomataLab builds an ε-NFA (result type ENFA) by composing Thompson fragments for union, concatenation, and Kleene star—each fragment has a start and accept state linked by ε-transitions.

    You can inspect the combined graph on the canvas before running further conversions.

  3. 3. Output — simulate or refine

    Test strings like abb (accept) vs ab (reject) with step simulation. Optionally chain ε-NFA → NFA then NFA → DFA for a deterministic view.

    Machine Studio canvas—use this view after the regex construct completes (desktop).

Automata & analysis

Subset construction (NFA → DFA)

Builds a DFA whose states are sets of NFA states—classic powerset construction.

Example: An NFA with two paths on input a becomes a DFA state {q0,q1}.

In AutomataLab: Machine Studio Convert dialog with step-by-step trace (desktop app only—the hosted demo does not include conversions).

Machine guide →
DFA minimization

Partition refinement (Hopcroft/Moore) to merge equivalent DFA states.

Example: Two distinguishable states on string ab stay separate; equivalent states merge.

In AutomataLab: Minimize DFA conversion on DFA input.

Machine guide →
ε-removal (ε-NFA → NFA)

Eliminates epsilon transitions while preserving the language.

Example: ε-closure adds reachable states before reading the next symbol.

In AutomataLab: ε-NFA → NFA conversion.

Machine guide →
Reachability & dead states

Finds states unreachable from the start and states that cannot reach acceptance.

Example: Prune unused branches before minimization or reporting.

In AutomataLab: Analyze panel in Machine Studio.

Grammar analysis

FIRST & FOLLOW

Computes terminal lookahead sets for CFG parsing and table construction.

Example: For E → T E', FOLLOW sets drive LL(1) table rows.

CNF & GNF transforms

In AutomataLab: Transformations tab (Type 2/3).

Ambiguity search

Searches for a string with two distinct parse trees (context-free grammars only).

Example: Classic dangling-else style grammars.

In AutomataLab: Ambiguity tab (Type 2 only—not regex or Type 3).

Bounded derivations (Types 0–1)

Searches for derivations with explicit depth/length limits.

Example: RESOURCE_LIMIT means “not found in time”, not a proof of non-membership.

What each grammar format unlocks

Grammar Lab and Parser Studio gate tools by Chomsky type. This table matches the application’s format checks—not every theoretical possibility.

Feature availability by grammar format in AutomataLab
Format Parser Studio FIRST/FOLLOW CNF/GNF transforms Ambiguity search Derivations Typical machine targets
Regex Yes (adapted to Type 3) No No No No (use Sampler) DFA–TM family
Type 3 Yes Yes Yes No Yes DFA–TM family
Type 2 (CFG) Yes Yes Yes Yes Yes NPDA, NLBA, TM
Type 1 (CSG) No No No No Yes (bounded) NLBA, TM
Type 0 No No No No Yes (bounded) TM

Regex and Type 3 grammars can be sent to a wide range of machine targets; Type 2 adds NPDA; Types 1 and 0 use bounded recognizers on NLBA or TM in Machine Studio.

Quickstart (desktop)

  1. Install — Download the Windows, Linux, or macOS build from Get AutomataLab (or build from source per the Contributing Guide).
  2. Workspace hub — Launch the app and pick a workspace from the hub (or Open File). Return via File → Go to Workspace Hub.
  3. Load an example — Open a bundled example or import .autolab.json / JFLAP .jff in Machine Studio.
  4. Simulate — Step or play execution; use batch tests where available.
  5. Go deeper — Press F1 for the User Manual and F2 for the Theory Handbook inside the app.

Prefer the browser? Launch the Machine Studio demo — Grammar Lab and Parser Studio require the desktop app.
