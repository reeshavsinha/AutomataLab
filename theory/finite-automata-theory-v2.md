## 1. The Chomsky Hierarchy & Formal Languages

Introduced by linguist Noam Chomsky, the **Chomsky Hierarchy** classifies formal grammars and languages based on their structural complexity [336, 1091]. Each class of languages is generated by a specific type of grammar and recognized by a corresponding class of abstract computing machines [336].

### Language Type Containment
The languages form a strict hierarchy of nested sets, where each level is a proper subset of the level above it:
$$\mathcal{L}_{Regular} \subset \mathcal{L}_{Context-Free} \subset \mathcal{L}_{Context-Sensitive} \subset \mathcal{L}_{Recursively-Enumerable}$$

Below is the definitive structural comparison matrix of the Chomsky Hierarchy:

| Chomsky Type | Grammar Name | Production Rules Constraints | Recognizing Automaton | Direct Practical Applications |
| :--- | :--- | :--- | :--- | :--- |
| **Type-3** | Regular Grammar (RG) | $A \to aB$ or $A \to a$<br>*(where $A, B \in V$ and $a \in T$)* [643-644] | **Finite Automata (FA)**<br>*(DFA, NFA, $\epsilon$-NFA)* [476-477] | Lexical Analyzers, Token Scanners (Flex), Pattern Matching (grep) [134, 340, 512] |
| **Type-2** | Context-Free Grammar (CFG) | $A \to \alpha$<br>*(where $A \in V$ and $\alpha \in (V \cup T)^*$)* [156, 201] | **Pushdown Automata (PDA)** [724, 747-748] | Syntactic Parsers (Yacc/Bison), Programming Language Syntax (C, Java) [204, 346, 620] |
| **Type-1** | Context-Sensitive Grammar (CSG) | $\alpha A \beta \to \alpha \gamma \beta$<br>*(where $\gamma \neq \epsilon$, and length of LHS $\le$ RHS)* [658] | **Linear Bounded Automata (LBA)** | Declaration validation, type checking, natural language processing syntax |
| **Type-0** | Unrestricted Grammar (UG) | $\alpha \to \beta$<br>*(no structural constraints on rewrite rules)* | **Turing Machines (TM)** [867-868, 966] | Theoretical limits of general computation, programming languages [335, 962] |

## 2. Deterministic & Nondeterministic Finite Automata (Type-3)

### Core Algebraic Elements
* **Alphabet ($\Sigma$)**: A finite, nonempty set of symbols [355].
* **String**: A finite sequence of symbols chosen from $\Sigma$ [356]. The length $|w|$ denotes the sequence length [356]. The empty string is denoted $\epsilon$ [356].
* **Language ($L$)**: A subset of $\Sigma^*$, representing a set of valid strings [357].

### Deterministic Finite Automata (DFA)
A DFA is a 5-tuple [384]:
$$M = (Q, \Sigma, \delta, q_0, F)$$
where:
* $Q$ is a finite set of states [383].
* $\Sigma$ is a finite input alphabet [383].
* $\delta: Q \times \Sigma \to Q$ is the deterministic transition function [383].
* $q_0 \in Q$ is the initial start state [384].
* $F \subseteq Q$ is the set of final/accepting states [384].

#### Extended Transition Function ($\hat{\delta}$)
To model processing of arbitrary string inputs recursively [393]:
* **Basis**: $\hat{\delta}(q, \epsilon) = q$ [394]
* **Induction**: $\hat{\delta}(q, xa) = \delta(\hat{\delta}(q, x), a)$ where $a \in \Sigma, x \in \Sigma^*$ [394]

#### Language of a DFA
$$L(M) = \{ w \in \Sigma^* \mid \hat{\delta}(q_0, w) \in F \}$$ [400]

```text
Algorithm 1: DFA Simulation
Input: String w, DFA M = (Q, Sigma, delta, q0, F)
Output: Accept/Reject

state = q0
while (not end of string) {
    a = get_next_char()
    state = delta(state, a)
}
if state in F: return Accept
else: return Reject
```

### Nondeterministic Finite Automata (NFA)
An NFA allows transitions to multiple states or zero states on an input symbol, returning a set of next states [407, 411]:
$$\delta_N: Q \times \Sigma \to \mathcal{P}(Q)$$

#### NFA-to-DFA Equivalence (The Subset Construction)
For every NFA $N$, we construct an equivalent DFA $D = (Q_D, \Sigma, \delta_D, q_D, F_D)$ [419]:
1. **States**: $Q_D = \mathcal{P}(Q_N)$ (power set of states) [419].
2. **Start State**: $q_D = \{q_0\}$ [419].
3. **Final States**: $F_D = \{ S \in Q_D \mid S \cap F_N \neq \emptyset \}$ [420].
4. **Deterministic Step Transition**: 
   $$\delta_D(S, a) = \bigcup_{p \in S} \delta_N(p, a)$$ [420]

#### Lazy Evaluation Algorithm
To avoid constructing all $2^{|Q_N|}$ states, many of which are unreachable, we generate states incrementally [422-423]:

```text
Algorithm 2: Lazy Subset Construction
Input: NFA N = (QN, Sigma, delta_N, q0, FN)
Output: Accessible DFA states QD, transitions delta_D

q_init = {q0}
QD = { q_init }
Queue = [ q_init ]
delta_D = empty_map

while (Queue is not empty) {
    S = pop(Queue)
    for each symbol a in Sigma {
        U = Union of delta_N(p, a) for all p in S
        if (U is not empty) {
            if U not in QD {
                add U to QD
                push U to Queue
            }
            delta_D(S, a) = U
        }
    }
}
FD = { S in QD | S intersects FN }
```

### Epsilon-Transitions ($\epsilon$-NFA)
Adding $\epsilon$-transitions allows spontaneous transitions without consuming input [436].
* **$\epsilon$-Closure**: $\text{ECLOSE}(q)$ is the set of all states reachable from $q$ following only $\epsilon$-labeled edges [440].

```text
Algorithm 3: Compute ECLOSE(S)
Input: Set of states S
Output: ECLOSE_Set

Stack = push all states in S
ECLOSE_Set = S
while (Stack is not empty) {
    t = pop(Stack)
    for each state u in delta(t, epsilon) {
        if u not in ECLOSE_Set {
            add u to ECLOSE_Set
            push u to Stack
        }
    }
}
return ECLOSE_Set
```

To convert an $\epsilon$-NFA to a DFA, set $q_{D} = \text{ECLOSE}(q_0)$ [447] and for each state $S \in Q_D$ and symbol $a \in \Sigma$, compute:
$$\delta_D(S, a) = \text{ECLOSE}\left( \bigcup_{p \in S} \delta(p, a) \right)$$ [448]

### DFA State Minimization
For every regular language, there exists a unique minimum-state DFA (excluding state names) [134].
* **Equivalent States**: Two states $p$ and $q$ are equivalent if for all strings $w \in \Sigma^*$, $\hat{\delta}(p, w) \in F \iff \hat{\delta}(q, w) \in F$ [597].
* **Distinguishable States**: States that are not equivalent [598].

#### The Table-Filling Algorithm (Hopcroft/Moore) [135, 598]:
1. Set up a grid of all pairs $\{p, q\}$ [598].
2. Mark $\{p, q\}$ if $p \in F$ and $q \notin F$ (or vice versa) [598].
3. For each unmarked pair $\{p, q\}$ and symbol $a \in \Sigma$, if $\{\delta(p, a), \delta(q, a)\}$ is marked, then mark $\{p, q\}$ [598]. Iterate until no new pairs are marked [598].
4. Equivalence classes of unmarked pairs partition the DFA into the minimized state blocks [604-605].

## 3. Context-Free Grammars & Pushdown Automata (Type-2)

Context-Free Grammars represent languages with nested recursive structures, such as expressions, blocks, and parameters [346, 619].

### Formal Definition of CFG
A CFG is defined as a 4-tuple [151, 628]:
$$G = (V, T, P, S)$$
where:
* $V$ is a finite set of **variables** (nonterminals) [624].
* $T$ is a finite set of **terminals** (tokens) [624].
* $P$ is a set of rewrite rules of the form $A \to \alpha$ (where $A \in V, \alpha \in (V \cup T)^*$) [625].
* $S \in V$ is the distinguished **start symbol** [625].

#### Derivations
* **Leftmost Derivation ($lm$)**: At each step, the leftmost variable is replaced [162, 635].
* **Rightmost Derivation ($rm$)**: At each step, the rightmost variable is replaced [162, 638].

### Parse Trees & Structural Representation
A **Parse Tree** is a visual representation of a derivation, showing how variables expand into yields of terminals [163, 645].

```text
      Parse Tree for a + a * a in expression grammar:
                     E
                   / | \
                  E  +  T
                  |     / | \
                  I    T  *  F
                  |    |     |
                  a    F     I
                       |     |
                       I     a
                       |
                       a
```

### Ambiguity and Syntax Parsing Issues
A grammar $G$ is **ambiguous** if there exists a string $w \in L(G)$ with multiple distinct parse trees (or multiple leftmost/rightmost derivations) [165, 646, 685].

#### Example: Dangling-Else Ambiguity
An ambiguous syntax structure [176, 669]:
$$\text{stmt} \to \text{if } \text{expr} \text{ then } \text{stmt} \mid \text{if } \text{expr} \text{ then } \text{stmt} \text{ else } \text{stmt}$$

To resolve this ambiguity and generate a unique parse tree, we rewrite the grammar to match every `else` with its nearest unmatched `if` [176]:
$$\begin{aligned}
\text{stmt} &\to \text{matched\_stmt} \mid \text{open\_stmt} \\
\text{matched\_stmt} &\to \text{if } \text{expr} \text{ then } \text{matched\_stmt} \text{ else } \text{matched\_stmt} \mid \text{other} \\
\text{open\_stmt} &\to \text{if } \text{expr} \text{ then } \text{stmt} \mid \text{if } \text{expr} \text{ then } \text{matched\_stmt} \text{ else } \text{open\_stmt}
\end{aligned}$$ [176]

#### Immediate Left-Recursion Elimination
Left-recursive productions ($A \to A\alpha$) cause top-down LL(1) recursive-descent parsers to loop infinitely [92, 146, 173]. We transform the rules as follows [178]:
$$A \to A\alpha_1 \mid A\alpha_2 \mid \beta_1 \mid \beta_2$$
becomes:
$$\begin{aligned}
A &\to \beta_1 A' \mid \beta_2 A' \\
A' &\to \alpha_1 A' \mid \alpha_2 A' \mid \epsilon
\end{aligned}$$ [178]

### Normal Forms for CFGs
Normal forms simplify CFGs for parser algorithms [777].

#### Chomsky Normal Form (CNF)
A grammar is in CNF if every production is in one of two forms [190, 797]:
$$A \to BC \quad \text{or} \quad A \to a$$
*(where $A, B, C \in V$ and $a \in T$, with final state blocks containing no useless symbols)* [190, 797].

**Steps to Convert an Arbitrary Grammar to CNF** [805]:
1. **Eliminate $\epsilon$-productions**: Find all nullable variables $A \xrightarrow{*} \epsilon$ [189, 785]. If a production is $B \to X_1 X_2$, create variations with nullable symbols present or absent [786].
2. **Eliminate unit productions**: Locate all unit pairs $A \xrightarrow{*} B$ where $A, B \in V$ [789-790]. Replace unit steps with non-unit alternatives [790, 794].
3. **Eliminate useless symbols**: Remove variables that cannot generate terminals, or are unreachable from the start symbol [778-779].
4. **Binarize Production Bodies**: Replace terminals in bodies of length $\ge 2$ with dedicated variables [798-799]. Cascade longer chains of variables: $A \to B_1 B_2 \dots B_k \implies A \to B_1 C_1, C_1 \to B_2 C_2 \dots$ [800].

#### Greibach Normal Form (GNF)
Every production in GNF starts with a terminal symbol, followed by zero or more variables [803-804]:
$$A \to a \alpha \quad (\text{where } a \in T, \alpha \in V^*)$$ [803]

### Pushdown Automata (PDA)
A Pushdown Automaton is a nondeterministic finite control enhanced with a Last-In, First-Out (LIFO) stack memory structure [721, 723-724].

Mathematically, a PDA is defined as a 7-tuple [728]:
$$P = (Q, \Sigma, \Gamma, \delta, q_0, Z_0, F)$$
where:
* $Q$ is the finite set of states [728].
* $\Sigma$ is the input alphabet [728].
* $\Gamma$ is the stack alphabet [729].
* $q_0 \in Q$ is the initial start state [730].
* $Z_0 \in \Gamma$ is the bottom-of-stack marker symbol [730].
* $F \subseteq Q$ is the set of accepting states [730].
* $\delta: Q \times (\Sigma \cup \{\epsilon\}) \times \Gamma \to \mathcal{P}(Q \times \Gamma^*)$ is the transition function [729].

#### Instantaneous Descriptions (IDs)
The full configuration of a PDA at any step is captured by a triple [732]:
$$(q, w, \alpha) \in Q \times \Sigma^* \times \Gamma^*$$
representing current state $q$, remaining input string $w$, and current stack content $\alpha$ (with leftmost symbol at the top) [732].

#### Acceptance Modes
1. **Acceptance by Final State**: 
   $$L(P) = \{ w \in \Sigma^* \mid (q_0, w, Z_0) \xrightarrow{*} (q, \epsilon, \alpha) \text{ for some } q \in F, \alpha \in \Gamma^* \}$$ [739-740]
2. **Acceptance by Empty Stack (Null Stack)**:
   $$N(P) = \{ w \in \Sigma^* \mid (q_0, w, Z_0) \xrightarrow{*} (q, \epsilon, \epsilon) \text{ for any state } q \in Q \}$$ [741-742]

These two models are equivalent: any PDA accepting by empty stack can be converted to one accepting by final state, and vice-versa, by wrapping the original states with extra transitions to handle a new bottom-of-stack sentinel [742-745].

### Deterministic Pushdown Automata (DPDA)
A DPDA must meet two constraints [758]:
1. $\delta(q, a, X)$ contains at most one element for any $q \in Q, a \in \Sigma \cup \{\epsilon\}, X \in \Gamma$ [759].
2. If $\delta(q, a, X)$ is nonempty for some $a \in \Sigma$, then $\delta(q, \epsilon, X)$ must be empty [759].

#### DPDA Properties
* $L_{\text{DPDA}}$ languages are unambiguous context-free languages [766].
* $L_{\text{DPDA}}$ accepts all Regular languages [761-762].
* Unambiguous languages like even-length palindromes ($L = \{ w w^R \}$) cannot be accepted by any DPDA, as they require nondeterminism to "guess" the center marker position [726-727, 759-760]. DPDAs can only accept them if a center marker is explicitly introduced ($L = \{ w c w^R \}$) [759].
* Acceptance by empty stack in a DPDA requires the language to have the **prefix property** (no word in the language is a prefix of another) [763, 772].

### Direct Compiler Application: Syntax Analysis (Parsing)
* **Top-Down Parsing (LL(1))**: Employs non-left-recursive CFGs to construct a predictive parsing table using $\text{FIRST}$ and $\text{FOLLOW}$ sets [146, 185]. LL(1) parsers operate like DPDAs that simulate derivations top-down [144, 203].
* **Bottom-Up Parsing (Shift-Reduce)**: Simulates the reverse of a rightmost derivation [157, 203]. Common parsers include:
  * **LR(0)**: Uses canonical sets of items and a DFA to make parsing transitions [193-194].
  * **SLR(1) / LALR(1)**: Resolves Shift/Reduce and Reduce/Reduce conflicts by examining lookahead terminals [194, 197]. LALR(1) merges states with matching core items, significantly saving memory [195, 198].
  * **CLR(1)**: Fully tracks lookahead information, providing the most powerful deterministic parser model [197].

## 4. Context-Sensitive Languages & Linear Bounded Automata (Type-1)

Context-Sensitive Grammars (CSGs) represent languages where rules apply only when symbols are surrounded by specific context symbols [658].

### Formal Definition of CSG
Productions are constrained to the form:
$$\alpha A \beta \to \alpha \gamma \beta$$
where $A \in V$ and $\gamma \in (V \cup T)^+$ (nonempty) [658]. Thus, rewrite rules can never contract the length of the sentential form: $|LHS| \le |RHS|$.

### Recognizing Automaton: Linear Bounded Automata (LBA)
An LBA is a restricted Turing Machine that has a single tape head, but the usable tape size is linearly bounded by the length of the input string.
* Formally, the tape is bounded by left and right endmarker symbols, which the tape head cannot cross.
* LBAs are extremely powerful but remain decidable, unlike Type-0 machines.

## 5. Turing Machines & Undecidability (Type-0)

A Turing Machine (TM) is the mathematical standard for general-purpose computers, defining the physical boundary of what can be computed [335, 868].

```text
               Abstract Turing Machine Model:
               
               +-----------------------------------+
               | ... | B | B | 0 | 1 | 1 | B | ... |  <-- Infinite Tape [882]
               +-----------------------------------+
                               ^
                               | Scan / Write
                       +---------------+
                       | Finite State  |  <-- Q (Finite Control) [882, 884]
                       |    Control    |
                       +---------------+
```

### Formal Definition of Turing Machine
A Turing Machine is represented as a 7-tuple [884]:
$$M = (Q, \Sigma, \Gamma, \delta, q_0, B, F)$$
where:
* $Q$ is a finite set of states [884].
* $\Sigma$ is a set of input symbols [884].
* $\Gamma$ is the set of tape symbols, where $\Sigma \subset \Gamma$ [884].
* $\delta: Q \times \Gamma \to Q \times \Gamma \times \{L, R\}$ is the transition function [884].
* $q_0 \in Q$ is the initial start state [884].
* $B \in \Gamma \setminus \Sigma$ is the designated blank symbol [884-885].
* $F \subseteq Q$ is the set of final/accepting states [885].

#### Instantaneous Descriptions (IDs) for TMs
An ID is written as:
$$X_1 X_2 \dots X_{i-1} q X_i X_{i+1} \dots X_n$$ [887]
which specifies that [887]:
1. The machine is in control state $q$.
2. The tape head is currently scanning symbol $X_i$.
3. The non-blank content of the tape is $X_1 X_2 \dots X_n$.

### Turing Machine Programming Techniques
* **Storage in State**: Structuring the state space as a tuple (e.g., $Q \times \Sigma$) to remember a finite amount of data while transitioning [910].
* **Multiple Tracks**: Treating tape symbols as vectors to divide a single physical tape into $k$ logical tracks [911].
* **Subroutines**: Defining modular segments of transitions with initial and return states, enabling reusable computations [914].

### Extensions of Turing Machines (Equivalent Power)
The following extensions do not expand the class of recognizable languages (they remain RE) but simplify programming [917-918]:
* **Multitape Turing Machines**: TMs with $k$ independent tapes, each with its own read-write head [918-919]. Can be simulated by a single-tape TM with multiple tracks [920].
* **Nondeterministic Turing Machines (NTMs)**: TMs that can make multiple choices of moves at each step [923]. Simulated deterministically by exploring a queue of reachable IDs systematically [924-925].

#### Counter Machines
A counter machine restricts the stack structure so that it can only store integers [931].
* **Theorem**: A **2-counter machine** can simulate a full Turing Machine and can recognize any Recursively Enumerable language [941, 943].

## 6. Computability, Decidability & Undecidability

Turing's goal was to describe the mathematical limits of general computing devices [335].

### Diagonalization Language ($L_d$) & Proof of Non-RE Status
To prove some problems cannot be solved by any computer, we represent Turing Machines as binary strings, allowing us to order all TMs: $M_1, M_2, \dots$ [980].
* **Diagonalization Language ($L_d$)**:
  $$L_d = \{ w_i \mid w_i \notin L(M_i) \}$$ [982]
  representing the set of all binary strings $w_i$ such that the $i$-th Turing Machine $M_i$ does not accept $w_i$ as input [980, 982].

#### Proof that $L_d$ is not Recursively Enumerable (non-RE):
Suppose $L_d$ is RE. Then there must exist some TM $M_j$ that accepts $L_d$: $L(M_j) = L_d$ [982]. 
Now, check if the string $w_j$ (the code for $M_j$) is in $L_d$ [982]:
* If $w_j \in L_d \implies M_j$ accepts $w_j \implies w_j \notin L_d$ (contradiction) [982].
* If $w_j \notin L_d \implies M_j$ does not accept $w_j \implies w_j \in L_d$ (contradiction) [982].

Thus, no such TM $M_j$ can exist. $L_d$ is mathematically non-computable (non-RE) [982].

### Decidability vs. Semi-Decidability
* **Recursive (Decidable) Languages**: A language $L$ is recursive if there exists a TM that always halts, returning **Accept** if $w \in L$ and **Reject** if $w \notin L$ [986]. This acts as a reliable **Algorithm** [986].
* **Recursively Enumerable (Semi-Decidable / RE) Languages**: A language $L$ is RE if there exists a TM that halts in an accepting state if $w \in L$, but may loop infinitely if $w \notin L$ [985].

#### Complement Theorem
If both a language $L$ and its complement $\overline{L}$ are Recursively Enumerable (RE), then $L$ is a Recursive (decidable) language [993-994].

```text
                  Containment of Language Classes (Computability):
                  
                  +----------------------------------------------+
                  |                 All Languages                |
                  |                                              |
                  |    +------------------------------------+    |
                  |    | Recursively Enumerable (RE)        |    |
                  |    | (e.g., Lu, Halting Problem) [988]  |    |
                  |    |                                    |    |
                  |    |    +--------------------------+    |    |
                  |    |    | Decidable (Recursive)    |    |    |
                  |    |    +--------------------------+    |    |
                  |    +------------------------------------+    |
                  |           |                                  |
                  |           +-- Non-RE (e.g., Ld) [982, 988]   |
                  +----------------------------------------------+
```

### The Halting Problem & The Universal Language
* **Universal Language ($L_u$)**: Set of all coded pairs $(M, w)$ such that TM $M$ accepts input $w$ [997]. $L_u$ is RE but **undecidable** [997, 1000].
* **The Halting Problem**: Set of all pairs $(M, w)$ such that $M$ halts on $w$, regardless of whether it accepts [1001]. This is RE but undecidable [1001].

### Rice's Theorem
For any **nontrivial property** $P$ of the languages accepted by Turing Machines, the language $L_P = \{ M \mid L(M) \in P \}$ is undecidable [1014-1015].
* A property is **nontrivial** if it is satisfied by some RE languages, but not all [1015].
* *Examples of Undecidable Properties*: Is $L(M)$ empty? Is $L(M)$ finite? Is $L(M)$ context-free? [1009, 1014, 1018].

### Post's Correspondence Problem (PCP)
An undecidable problem involving two lists of strings $A = w_1, w_2, \dots, w_k$ and $B = x_1, x_2, \dots, x_k$ [1022, 1029]. The goal is to find a sequence of indices $i_1, i_2, \dots, i_m$ such that:
$$w_{i_1} w_{i_2} \dots w_{i_m} = x_{i_1} x_{i_2} \dots x_{i_m}$$ [1027, 1029]

#### Application of PCP
By reducing PCP, we prove that crucial questions about Context-Free Grammars are undecidable, such as [1037]:
1. Is a given CFG $G$ ambiguous? [854, 1037]
2. Is a given CFL inherently ambiguous? [854]
3. Is $L(G_1) \cap L(G_2)$ empty? [854, 1037]

## 6. Complexity Theory & Intractability

Complexity theory classifies decidable languages based on the computation time or space required to solve them [348].

### The Classes P and NP
* **Class P**: Languages solvable by a deterministic Turing Machine in polynomial time: $T(n) = O(n^k)$ [348, 1045].
* **Class NP**: Languages solvable by a nondeterministic Turing Machine in polynomial time [1045-1046].

### NP-Completeness
A language $L$ is **NP-complete** if [1046]:
1. $L \in NP$ [1046].
2. For every language $L' \in NP$, there exists a polynomial-time reduction $L' \le_P L$ [1046].

* **The Cook-Levin Theorem**: The boolean satisfiability problem (**SAT**) is NP-complete [1052, 1058].

### Polynomial Space (PSPACE)
* **Class PS (PSPACE)**: Languages solvable by a TM in polynomial space [1060, 1064].
* **Savitch's Theorem**: Nondeterminism does not increase the power of space-bounded computation:
  $$PSPACE = NPSPACE$$ [1060, 1064]

## 7. Syntax-Directed Translation & Intermediate Representation

In practical compiler design, compilers leverage Type-3 and Type-2 models to build structural representations of code, compile expressions, and optimize translations [26, 41, 226].

### Syntax-Directed Definitions (SDDs)
An SDD associates **attributes** with grammar symbols and **semantic rules** with productions [87, 214]:
* **Synthesized Attribute**: Computed bottom-up from the attribute values of its children in the parse tree [213].
* **Inherited Attribute**: Computed top-down from parent or sibling attribute values [213, 215].

#### Classes of SDDs
* **S-Attributed Definitions**: Uses only synthesized attributes [213]. Can be evaluated during bottom-up parsing transitions [213].
* **L-Attributed Definitions**: Uses synthesized or inherited attributes, but the evaluation rules are restricted to left-to-right dependencies (attributes of child $X_i$ can only depend on parent or left sibling $X_1, \dots, X_{i-1}$) [213, 223].

### Intermediate Representations (IR)
To insulate the language front-end from target-specific hardware details, the parser compiles structural representations into IR [42-43, 226]:

#### Abstract Syntax Trees (ASTs) vs. Directed Acyclic Graphs (DAGs)
* **AST**: Depicts the exact hierarchical structure of expressions, preserving duplicate operators and operands [94, 96, 226].
* **DAG**: An optimized representation that merges duplicate leaf and subexpression nodes to avoid redundant calculations [229, 264].

```text
         AST vs. DAG for the expression a + b - (a + b):
         
                 AST                                  DAG
                  -                                    -
                /   \                                /   \
               +     +                              +     |
              / \   / \                            / \    /
             a   b a   b                          a   b --+
```

Compilers leverage these structures to generate optimized lower-level linear intermediate code, such as **Three-Address Code (3AC)** [42, 96, 226-227].
